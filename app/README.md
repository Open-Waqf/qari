# 📱 Qari Finder App

The frontend application for Qari Finder. It handles high-fidelity microphone input, real-time feature extraction, and
neural network inference locally in the browser.

## 🧠 The Engineering Pipeline

The app is designed as a "Digital Twin" of the Python training environment, ensuring that what the model "hears" in
production is identical to what it "learned" in the lab.

1. **The Ear (Mic):** Captures raw audio (typically 48kHz).
2. **The Resampler (Worklet):** Uses a high-quality **Hermite Cubic Interpolator** to downsample to 22.05kHz. This
   prevents aliasing artifacts that common linear resamplers cause.
3. **The Math Bridge (Extractor):** Uses custom matrix multiplication for FFT and Mel-scaling to guarantee bit-parity
   with Python's `librosa`.
4. **The State Machine (Hysteresis):** A session-locking layer that filters AI predictions to ensure UI stability,
   preventing flickering results during pauses or background noise.
5. **The Brain (TFJS):** Executes the CNN model using WebGL/WebAssembly acceleration.

## 🏗️ Project Architecture

* `src/core/audio-manager.ts`: Manages hardware lifecycle, permissions, and the AudioWorklet.
* `src/model/inference-engine.ts`: The core state machine; handles session locking, stability, and TFJS execution.
* `src/features/custom-extractor.ts`: The DSP engine. Contains the FFT/DCT matrices exported from Python.
* `src/debug/DebugPanel.ts`: 🆕 **Engineering Dashboard.** Live monitoring of latency, RMS, and DSP stats.
* `public/processors/resampler-processor.js`: Low-latency cubic resampler running in a separate thread.

## 🐞 Engineering & Debug Tools

To access advanced tools, append `?debug=1` to your URL. These tools are designed to isolate errors across the pipeline.

### ⚖️ The Strict Parity Test (The Judge)

The **Math** button in the Debug Panel runs a mathematical audit:

* It loads a "Golden Reference" signal and MFCC result generated by Python.
* It runs the same signal through the JS extractor.
* It asserts that the results match within a tolerance of `0.00005`.
* **Purpose:** Proves that a failure is due to the *model* and not a *bug in the DSP math*.

### 🧪 Inference Toggles

* **RMS Normalize:** Toggles linear gain adjustment to target -20dB RMS.
* **Pre-Emphasis:** Toggles high-frequency boost ().
* **CMVN:** Toggles Cepstral Mean and Variance Normalization.

### 🎧 Capture & Evaluation

* **Shift+M (MicCap):** Captures **post-worklet 22k PCM** exactly as the model sees it. Saves as a `.wav` and runs an
  immediate diagnostic test.
* **Shift+L (Loopback):** Feeds an audio file through the *entire* hardware simulation (48k Context → Cubic Resampler →
  Buffer) to stress-test the live pipeline.
* **Shift+T (FileTest):** Direct evaluation of a file to check model accuracy on clean data.

### 📱 Live Stats

* **TF Backend:** Monitors if the app is using `webgl` (fast) or `wasm` (fallback).
* **Latency:** Calculates the "Glass-to-Ear" delay between audio input and prediction.
* **Noise Floor:** Live tracking of the adaptive noise gate baseline.
